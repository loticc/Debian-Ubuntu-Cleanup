# Debian-Ubuntu-Cleanup

**Debian / Ubuntu VPS 精简与初始化脚本**

一个用于 Debian 和 Ubuntu VPS 的系统精简与基础环境初始化脚本，主要面向不需要图形桌面、希望减少系统冗余组件的服务器。

脚本会安装常用网络与系统管理工具，尝试移除桌面环境相关组件和无用依赖，启用 SSH 与 Cron 服务，将默认启动目标设置为 `multi-user.target`，并设置系统时区。

> **重要提醒：** 本脚本会通过 APT 卸载软件包，并可能删除桌面环境相关组件。请在执行前阅读本文、检查脚本源码，并为重要服务器创建快照或备份。不要直接在不了解其操作影响的生产服务器上运行。

## 功能介绍

### 1. 系统更新与基础工具安装

脚本执行 `apt update`，并尝试安装以下软件包：

| 软件包 | 主要用途 |
|---|---|
| `curl` | 下载文件及访问网络资源 |
| `ca-certificates` | 提供常用 CA 证书 |
| `wget` | 下载文件 |
| `gnupg` | 处理 GPG 密钥和签名 |
| `tasksel` | 查询系统软件任务 |
| `openssh-server` | 提供 SSH 远程登录服务 |
| `cron` | 提供定时任务服务 |
| `iproute2` | 查看和管理网络接口、路由等 |
| `procps` | 提供进程及系统信息工具 |
| `ifupdown` | 提供传统网络接口管理工具 |
| `net-tools` | 提供 `ifconfig`、`netstat` 等传统工具 |

脚本使用 `--no-install-recommends`，尽量避免安装非必需的推荐依赖。

请注意，安装 `ifupdown` 并不代表脚本会自动迁移或修复网络配置。已有的 Netplan、systemd-networkd 或云平台网络管理方式仍需单独检查。

### 2. 移除桌面环境相关组件

脚本会尝试查询并移除以下桌面任务：

- `desktop`
- `ubuntu-desktop`

同时尝试清理部分 X 服务器和显示管理器组件，包括：

- `xserver-xorg-core`
- `xserver-xorg`
- `gdm3`
- `lightdm`
- `sddm`

具体能够卸载哪些组件，取决于系统当前安装的软件包和依赖关系。

随后脚本会执行：

```bash
apt autoremove --purge -y
apt clean
```

这些操作会删除 APT 认为不再需要的软件包，并清理本地软件包缓存。

**风险提示：** `apt autoremove --purge -y` 不会要求你逐个确认即将删除的软件包。如果系统中存在特殊依赖、手动安装的网络管理工具或其他关键组件，请先检查源码及依赖关系。不要将本脚本视为经过验证的通用瘦身工具。

### 3. 设置默认启动目标

脚本执行：

```bash
systemctl set-default multi-user.target
```

这会将系统默认启动目标设置为 `multi-user.target`，适合不需要图形桌面的常规服务器环境。

该设置不等于保证所有图形组件立即停止运行。如果服务器需要桌面环境，请不要直接执行本脚本。

### 4. 启用 SSH 和 Cron 服务

脚本会尝试执行：

```bash
systemctl enable --now ssh
systemctl enable --now cron
```

其目的是启用并启动 SSH 服务与 Cron 服务。

这并不代表脚本会自动修改 SSH 端口、开放防火墙端口或配置云平台安全组。请根据服务器当前的服务配置及防火墙规则进行检查。

### 5. 检查基础网络状态

脚本会检查：

- 是否存在 `/etc/network/interfaces` 中的传统网络接口配置。
- 是否存在 `/etc/netplan` 中的 YAML 配置。
- 是否检测到默认路由。

如果没有找到预期的网络配置或默认路由，脚本会显示警告。

这些检查仅用于提示潜在问题，不会自动修复网络故障，也不能保证服务器重启后一定可以正常联网。

### 6. 设置系统时区

脚本会将系统时区设置为：

```text
Asia/Shanghai
```

这适用于希望使用中国标准时间的服务器。

如果你位于其他时区，或者你的应用要求使用 UTC，请注意这一行为。脚本当前不是交互式时区选择工具，运行前应确认该设置符合自身需求。

### 7. 日志记录与重启选项

脚本会将执行输出同时显示在终端并追加到：

```text
/var/log/vps-init.log
```

执行接近结束时，脚本会显示部分最终状态，并询问是否立即重启：

```text
是否现在重启？(y/N):
```

输入 `y` 或 `Y` 会尝试执行重启；直接回车或输入其他内容则跳过重启。

如果你刚修改过网络或 SSH 相关配置，建议先检查状态，再决定是否重启。

## 适用系统

项目当前声明的目标系统为：

| 系统 | 目标版本 |
|---|---|
| Debian | 12、13 |
| Ubuntu | 22.04、24.04 |

以上是项目的目标支持范围，不代表已经在所有云平台、系统镜像和网络环境中验证通过。

脚本会识别当前操作系统。对于非 Debian / Ubuntu 系统，它会显示兼容性警告，但这不构成完整的兼容性保护。

不建议在以下环境直接运行：

- 需要图形桌面的 VPS 或工作站。
- 已经部署重要业务的生产服务器。
- 使用复杂自定义网络配置、特殊软件依赖或定制启动流程的系统。
- 无法通过服务商控制台、VNC 或救援模式恢复的远程服务器。

## 执行前准备

### 1. 创建快照或备份

如果服务商提供快照功能，建议在执行前创建快照。

至少应提前保存：

- 重要数据和数据库。
- SSH 服务配置。
- 网络配置文件。
- 关键服务的配置文件。
- 当前安装的软件包清单。

例如，可以记录当前已安装的软件包：

```bash
dpkg-query -W > /root/packages-before-cleanup.txt
```

这份清单仅用于记录，不等同于系统备份，也不能保证所有软件包都可以完整恢复。

### 2. 确认拥有管理权限

脚本需要 root 权限。

查看当前用户：

```bash
whoami
```

如果返回：

```text
root
```

可以直接运行后面的 root 版本命令。

### 3. 确认远程管理方式可用

开始前，请确保你知道如何进入 VPS 服务商的管理面板，并且具备恢复系统或重新安装系统的能力。

仅通过 SSH 连接管理的服务器，应格外谨慎地进行网络及系统组件清理。

## 一键安装与运行

### 方法一：root 用户一键运行

如果当前终端已经是 root，例如：

```text
root@debian:~#
```

执行以下命令：

```bash
apt-get update && apt-get install -y curl ca-certificates && curl -fsSL https://raw.githubusercontent.com/loticc/Debian-Ubuntu-Cleanup/main/vps-init.sh -o /tmp/vps-init.sh && bash /tmp/vps-init.sh
```

该命令会依次：

1. 更新 APT 软件包索引。
2. 安装 `curl` 和 `ca-certificates`。
3. 从 GitHub 下载 `vps-init.sh`。
4. 执行下载的脚本。

**请注意：** 这是一条执行远程脚本的命令。运行前建议先阅读脚本源码，确认其中的卸载、时区和服务管理操作符合预期。

### 方法二：普通用户一键运行

如果当前使用的是普通用户，并且系统已配置 `sudo`，执行：

```bash
sudo apt-get update && sudo apt-get install -y curl ca-certificates && curl -fsSL https://raw.githubusercontent.com/loticc/Debian-Ubuntu-Cleanup/main/vps-init.sh -o /tmp/vps-init.sh && sudo bash /tmp/vps-init.sh
```

执行过程中可能需要输入当前用户的 sudo 密码。

### 方法三：先下载，再检查源码

如果希望在执行前阅读完整脚本，可以分两步操作。

第一步，下载脚本：

```bash
curl -fsSL https://raw.githubusercontent.com/loticc/Debian-Ubuntu-Cleanup/main/vps-init.sh -o /tmp/vps-init.sh
```

第二步，阅读脚本：

```bash
less /tmp/vps-init.sh
```

确认脚本内容符合预期后，再运行：

```bash
bash /tmp/vps-init.sh
```

以上示例假设当前用户为 root。如果不是 root，请使用 `sudo bash /tmp/vps-init.sh`。

### 关于脚本文件名

本仓库当前使用的脚本文件名是：

```text
vps-init.sh
```

正确的下载地址为：

```text
https://raw.githubusercontent.com/loticc/Debian-Ubuntu-Cleanup/main/vps-init.sh
```

请勿继续使用旧命令中的 `minimize.sh`，除非仓库后续确实创建并提交了这个文件。

## 脚本执行流程

运行脚本后，主要流程如下。

| 阶段 | 操作 | 可能的影响 |
|---|---|---|
| 前置检查 | 检查 root 权限及系统信息 | 非 root 用户会退出 |
| 日志设置 | 写入 `/var/log/vps-init.log` | 持续追加脚本输出 |
| 阶段一 | 更新软件包索引并安装基础工具 | 可能安装或更新软件包 |
| 阶段一 | 尝试清理桌面环境和无用依赖 | 可能卸载已有软件包 |
| 阶段一 | 启用 SSH、Cron 服务 | 改变服务运行与启动状态 |
| 阶段一 | 设置默认启动目标 | 改变默认启动模式 |
| 阶段二 | 设置时区为 `Asia/Shanghai` | 改变系统显示时间 |
| 最终检查 | 显示部分服务和网络状态 | 帮助发现部分异常 |
| 最后一步 | 询问是否立即重启 | 根据输入决定是否尝试重启 |

脚本使用非交互式 APT 环境，并对部分卸载操作的错误进行了忽略处理。因此，不能只依据终端中出现“执行完成”的文字来确认每一项操作都成功。

## 执行完成后的检查

建议在脚本运行结束后检查以下项目。

### 1. 检查操作系统版本

```bash
cat /etc/os-release
```

### 2. 检查默认启动目标

```bash
systemctl get-default
```

预期结果为：

```text
multi-user.target
```

### 3. 检查 SSH 服务

```bash
systemctl status ssh --no-pager
```

如果当前系统的服务单元名是 `sshd`，请使用：

```bash
systemctl status sshd --no-pager
```

### 4. 检查 Cron 服务

```bash
systemctl status cron --no-pager
```

### 5. 检查当前时区

```bash
timedatectl
```

也可以执行：

```bash
date
```

注意，显示正确的本地时间不代表时间同步服务一定正常。

### 6. 检查网络和默认路由

```bash
ip addr
ip route
```

如果没有预期的默认路由，或者发现网络接口状态异常，请先排查网络问题，不要急于重启服务器。

## 网络与 SSH 注意事项

### 1. 不要混淆 SSH 服务和 SSH 端口

本脚本会尝试安装及启用 OpenSSH Server，但不负责将 SSH 端口从 `22` 修改为其他端口。

如果你还需要修改 SSH 端口，应单独使用相应的管理工具，并提前配置防火墙规则。

### 2. 检查云平台防火墙

某些 VPS 除了系统内部的防火墙，还使用服务商安全组或云防火墙。

即使 SSH 服务正常运行，如果云平台未放行相应 TCP 端口，外部仍可能无法连接。

### 3. 重启前进行验证

不要仅因为脚本结束就认定服务器可以安全重启。至少确认：

- SSH 服务处于正常状态。
- 网络接口及默认路由正常。
- 重要业务服务没有受到影响。
- 已准备好服务商控制台或救援方式。

### 4. 不要忽略桌面环境卸载的影响

如果服务器安装过桌面、远程桌面、图形管理工具或依赖 X Server 的应用，执行清理后可能无法再使用这些功能。

如果 VPS 只用于命令行服务，这些清理操作才可能符合预期。

## 常见问题

### Q1：执行命令时出现 404 错误怎么办？

首先检查下载 URL 和仓库中的文件名。

正确文件名：

```text
vps-init.sh
```

正确地址：

```text
https://raw.githubusercontent.com/loticc/Debian-Ubuntu-Cleanup/main/vps-init.sh
```

如果仍然出现 404，请打开 GitHub 仓库，确认文件存在于 `main` 分支的根目录中，并检查文件大小写及路径是否一致。

### Q2：为什么 `apt-get update` 成功，脚本却没有运行？

`apt-get update` 只负责更新软件包索引，不能证明后续的下载和脚本执行一定成功。

请分别确认：

1. `curl` 是否能够正常访问 GitHub。
2. 下载地址是否正确。
3. 下载的文件是否存在且非空。
4. Bash 执行脚本时是否出现错误。

### Q3：脚本会自动修改 SSH 端口吗？

不会。当前脚本主要处理基础软件包、桌面环境清理、服务启用、启动目标和时区。SSH 端口管理需要另外操作。

### Q4：脚本运行结束后必须重启吗？

不一定。脚本会询问是否立即重启。

如果不确定服务或网络状态是否正常，可以先选择不重启，检查日志、服务状态及网络配置后再决定。

不过，部分更改可能要到重启后才会完整体现。

### Q5：运行后内存占用一定会降低吗？

不能保证。脚本的目标是精简桌面环境和部分冗余依赖，但实际内存占用取决于系统镜像、当前运行服务、应用程序和工作负载。

建议运行前后使用相同条件测量，比较实际资源占用。

### Q6：设置时区后，为什么时间仍然不正确？

时区只影响本地时间显示，并不负责保证系统时钟准确。请检查系统时钟和时间同步服务：

```bash
timedatectl status
```

## 故障排查与恢复

### 1. SSH 无法连接

优先通过 VPS 服务商控制台、VNC 或救援模式进入系统，然后依次检查：

```bash
ip addr
ip route
systemctl status ssh --no-pager
```

如果服务单元名不同，请使用 `sshd` 进行检查。

还需要确认服务商安全组、防火墙以及 SSH 实际监听端口。

### 2. 网络异常

检查网络接口、路由以及系统网络配置：

```bash
ip addr
ip route
```

然后检查相应配置文件，特别是：

```text
/etc/network/interfaces
/etc/netplan/
```

具体应使用哪种网络管理方式，取决于 VPS 镜像和服务商配置。不要在没有确认当前网络管理方式的情况下，直接覆盖网络配置文件。

### 3. 软件包被误删

如果发现某些必要的软件包被移除，应通过控制台查看 APT 历史记录、日志以及当前依赖状态，再决定是否重新安装。

可检查：

```bash
less /var/log/apt/history.log
```

也可搜索 APT 终端日志：

```bash
less /var/log/apt/term.log
```

注意：重新安装单个软件包未必能恢复其配置文件、依赖关系和此前的服务状态。

### 4. 系统无法启动

如果重启后无法正常启动或无法联网，请使用服务商提供的救援环境或快照恢复机制。

恢复操作应根据实际原因选择。不要在无法确认文件内容的情况下，直接删除配置文件或批量重装软件包。

## 卸载与回滚说明

本项目不是一个带有完整反向操作的安装器，因此**不存在仅删除脚本文件就能还原原始系统的通用卸载命令**。

脚本执行后可能已经：

- 安装或卸载软件包。
- 改变系统默认启动目标。
- 启用或启动服务。
- 改变系统时区。
- 清理 APT 缓存和无用依赖。

删除下载的临时脚本并不能撤销这些变更。

如需恢复，请根据执行前的快照、备份、APT 历史记录和系统配置进行处理。对于重要服务器，优先考虑恢复执行前的快照。

## 安全说明

- 运行脚本需要 root 权限，应先检查完整源码。
- 脚本会通过 APT 安装、卸载软件包，可能影响已有环境。
- 自动卸载和自动清理操作不能保证适用于所有 VPS 镜像。
- 脚本会将时区设为 `Asia/Shanghai`，运行前应确认需求。
- 脚本不会自动配置所有防火墙规则，也不会自动修复所有网络问题。
- 执行前建议创建快照，并确保拥有可用的控制台或救援方式。
- 请不要将脚本执行后的提示信息视为系统所有组件均正常的保证。
